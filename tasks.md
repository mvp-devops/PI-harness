# Пошаговый план реализации «Pi Harness Control»

План разбит на этапы, каждый этап заканчивается проверяемым результатом (критерий «Готово»). Порядок внутри этапов — рекомендуемый; этапы выполняются последовательно.

---

## Этап 0. Подготовка проекта

- [ ] 0.1. Инициализировать Vite + React + TypeScript проект (`npm create vite@latest . -- --template react-ts`).
- [ ] 0.2. Установить зависимости: `react-router-dom`, `zustand`, `@tanstack/react-query`, `tailwindcss`, `lucide-react`.
- [ ] 0.3. Настроить Tailwind CSS (postcss, base-стили, сброс).
- [ ] 0.4. Настроить пути/алиасы (`@/…`) в `tsconfig` и `vite.config.ts`.
- [ ] 0.5. Настроить ESLint + Prettier, добавить npm-скрипты: `dev`, `build`, `lint`.
- [ ] 0.6. Создать каркас каталогов по ТЗ: `src/app`, `src/components/{layout,ui,jobs,tasks,logs,settings}`, `src/features/{jobs,tasks,logs,settings}`, `src/lib/{api,utils}`, `src/types`, `src/mocks`.

**Готово, когда:** `npm run dev` открывает пустую страницу без ошибок, `npm run build` проходит.

---

## Этап 1. Дизайн-система и базовая инфраструктура

- [ ] 1.1. Определить дизайн-токены в Tailwind-конфиге: colors (нейтральная палитра + один акцент — тёмно-зелёный или индиго), spacing, radii (8–12 px), shadows, typography (system font stack / Inter, mono для ID/команд/логов).
- [ ] 1.2. Реализовать темы: light (по умолчанию), dark, system. Хранение выбора в Zustand, применение через CSS-переменные / `class="dark"`.
- [ ] 1.3. Создать базовые UI-компоненты в `components/ui`: Button, Input, Textarea, Select, Badge (статус), Card, Modal (подтверждение), Toast, Tabs, ProgressBar, Checkbox, EmptyState, Spinner.
- [ ] 1.4. Прокинуть типы домена в `src/types`: `Job`, `JobStatus` (Draft, Queued, Running, Paused, Waiting approval, Completed, Failed, Cancelled), `Task`, `TaskStatus`, `LogEntry` (level: info/warn/error), `RuntimeStatus`, `JobFilters`, `LogFilters`.
- [ ] 1.5. Добавить утилиты в `lib/utils`: форматирование времени/длительности, статусные бейджи (цвет + иконка + текст — различимы не только цветом), cn-хелпер для классов.

**Готово, когда:** токены и UI-кит доступны для экранов; тёмная тема переключается вручную.

## Этап 2. Mock API-слой и контракт `harnessApi`

- [ ] 2.1. Реализовать интерфейс/контракт API в `lib/api`: `startJob(requirement, options)`, `getJobs(filters)`, `getJobById(id)`, `pauseJob(id)`, `resumeJob(id)`, `cancelJob(id)`, `retryJob(id)`, `getTasks(jobId?)`, `getLogs(jobId?, filters)`, `subscribeToJobEvents(jobId, callback)`, `getRuntimeStatus()`.
- [ ] 2.2. Написать mock-реализацию в `src/mocks`: генерация jobs/tasks/logs, имитация задержек сети, прогресса и статусов.
- [ ] 2.3. Реализовать имитацию streaming-событий (заготовку под WebSocket/SSE): подписка на job-события через setTimeout/интервал, изменение прогресса и запись логов в реальном времени.
- [ ] 2.4. Реализовать `getRuntimeStatus()` с состояниями Connected / Disconnected / Reconnecting и периодической сменой для демо.
- [ ] 2.5. Добавить фабрику/переключатель провайдера (`createHarnessApi`): mock ↔ real, чтобы экраны не зависели от реализации (замена без переписывания UI).

**Готово, когда:** вызовы API через mock работают асинхронно; события job приходят подписчикам; контракт документирован в `README`.

- [ ] 3.5. Доступность: keyboard navigation, focus states, aria-labels, контраст WCAG AA.
- [ ] 3.6. Подключить Toast-контейнер (правый нижний угол) и глобальный обработчик ошибок API.

**Готово, когда:** навигация между всеми разделами работает, пустые маршруты ведут на свои экраны-заглушки.

**Готово, когда:** данные экранов приходят из query-хуков; live-обновления видны; действия job обновляют UI оптимистично.
